# Governance & Safety Gateway

## "Every Money Action Explainable, Bounded, and Gated"

The core judging bar for **Track 1: AI Growth & Agentic Commerce** is ensuring that autonomous agents cannot arbitrarily execute money-moving actions without explicit policy justification, budget checks, and cryptographic token verification.

---

## 1. Structural Gate Mechanism

Money-moving tools (`create_payment_link`, `create_upi_mandate`, `apply_offer`, `refund`) **structurally reject execution** if invoked without a valid `authorization_ref` generated by `request_preauthorization`.

```
               [ AI Buyer Agent ]
                       │
                       │ 1. request_preauthorization(action, amount, reason)
                       ▼
          [ Governance Gateway ]
          ├── Checks Spending Limits (Per-Tx, Daily, Monthly)
          ├── Autonomous Approval Threshold (<= ₹35,000)
          └── Reasoning Justification Validation
                       │
       ┌───────────────┼───────────────┐
       ▼               ▼               ▼
   [ Approved ]  [ Needs Human ]   [ Denied ]
   (Issues Auth  (High Value >     (Budget Exceeded /
    Reference)    ₹35,000 Step-Up)  Policy Violation)
       │
       │ 2. create_payment_link(order_id, authorization_ref)
       ▼
  [ Execution Gate ]
  ├── Validates token exists
  ├── Validates token not expired (15m TTL)
  ├── Validates single-use (rejects double spend)
  └── Atomically spends token & updates velocity
       │
       ▼
  [ Razorpay Test Rails Link Generated ]
       │
       ▼
  [ Immutable Audit Log Entry Written ]
```

---

## 2. Real Policy States (Non-Stubbed)

1. **`approved`**: Returned when the amount is within velocity limits and autonomous approval thresholds. Yields a single-use `authorization_ref` valid for 15 minutes.
2. **`needs_human_confirmation`**: Returned for transactions exceeding the autonomous threshold (> ₹35,000). Halts autonomous checkout and requests human step-up authorization.
3. **`denied`**: Returned when hard spending caps are violated or missing natural-language justifications.

---

## 3. Deliberate Failure Handling & Resilience

When a test-mode payment fails (e.g. `simulate_failure = 'bank_timeout'` or `payment_declined`):
1. Order state transitions to `failed` with structured `failure_details`.
2. `check_status` inspects the state and returns:
   - `can_retry: true`
   - `natural_language_diagnosis`: plain English explanation of the failure reason.
   - `suggested_next_action`: recommended alternative (e.g. UPI AutoPay mandate or retry).
3. The autonomous agent initiates recovery by requesting pre-authorization for the fallback rail and logs the entire resolution sequence to the immutable audit ledger.
